# Bootstrap — Upgrade

用于把现有项目升级到 agent.protocol v0.3，尤其是从 v0.2 的 `.ai/` 结构迁移。

协议仓：https://github.com/AlloVince/agent.protocol

按 `docs/spec.md` 的文档语言规则，本次生成或更新的文档标题、说明正文及输出报告默认使用简体中文；仅当前人类指令或项目明确的语言规则可覆盖。保留模板中的默认中文文档规则；代码、命令等保留原样，不批量翻译无关文档，不修改 `owner/`。

## 一次发起的范围

在 `.super` 总仓提交本升级任务，默认升级总仓及其明确声明的全部子仓，不需要逐仓再次提交提示词或确认。人类明确指定“仅总仓”、指定子仓或仅要求 review/预览时，以该范围为准。在普通仓或单个子仓发起时，默认只升级当前仓。

一次任务覆盖多仓，不表示一个 Git commit 可以更新所有独立仓；除非人类明确要求，仍不自动 commit/push。

## 先做

1. 识别仓库角色，按上述默认范围及人类指令确定目标仓。从总仓已有 `AGENTS.md`、README、仓库地图或 workspace 声明枚举全部子仓并核实位置，不将所有相邻目录自动视为子仓。
2. 阅读新版本 `README.md`、`docs/upgrade.md`；普通仓/子仓读 `templates/AGENTS.project.md`，总仓读 `templates/AGENTS.super.md`；涉及多仓时再读 `docs/multi-repo.md` 和适用的系统规则。
3. 阅读项目当前 `AGENTS.md`、`.ai/`（若存在）、README、owner（只读）、相关 docs 与原生配置。查明旧版来源，并核实本次使用的 tag/commit 或未发布修改状态。
4. 比较旧版、新版和项目定制，建立“旧规则 → 保留/修改/删除/替代及落点”表；来源不明或有冲突的规则先保留并报告，不先删除任何内容。

## 迁移

按 `docs/upgrade.md` 分类迁移：

- 通用/项目级 Agent 规则 → `AGENTS.md`
- 可由原生配置表达的事实 → 回到原生配置，不重复写
- 对未来 Agent 有明确收益的稳定知识 → 普通 `docs/`
- 人类长期意图 → 只列出给人确认，不自动写 `owner/`
- session 进度/流水账 → 不进入 docs；未完成任务在当前对话或已有任务载体交接后删除旧状态，不另建 memory
- workflow → 不迁移为新 workflow；只抽出仍有效的行为约束

全系统升级先处理 `.super`，再逐仓最小更新已授权的子仓；仅升级子仓时读取系统约束，不顺带修改其他仓。已有同步授权就直接执行，不重复索要确认。按 `docs/upgrade.md` 记录参考基线，并报告未同步仓及原因。

## 多仓执行

1. 本轮固定同一份协议来源（tag/commit，或明确的未发布内容），避免处理不同子仓时重新取最新版。
2. 对每个目标仓读取自身规则，检查工作树和目标文件的已有改动；保留用户工作，不 reset、不整文件覆盖。无法安全合并的文件保留原状并报告。
3. 总仓完成后，逐个子仓按 project 模板迁移并验证；已经符合的仓标记为“无需变更”，不为版本一致制造 diff。
4. 遇到无法访问、位置不明或冲突的仓，记录原因并继续处理其余不受影响的仓；依赖未决系统规则的部分暂不传播。不能遇到一个失败就遗漏剩余仓。
5. 对照最初枚举清单逐仓汇总：已更新、无需变更、部分完成或未处理，以及验证结果和剩余原因。未覆盖全部目标时明确报告部分完成，不把“已尝试”当成已升级。

## 升级检查

按仓库角色确认新 `AGENTS.md` 已覆盖适用约束；总仓还要检查职责、契约、规则传播与整体验收：

- owner 只读与权威顺序
- 默认中文文档规则已保留；检查本次文档标题与说明正文的语言，使用其他语言时说明对应的明确要求，不能仅沿用现有英文内容推定语言规则
- 真实任务导航、正式命令与共享能力入口；子仓能够定位所属 `.super`
- 按 `docs/spec.md` 检查正文、链接、注释和命令示例中的个人机器路径；改成可迁移导航，不能只替换用户名或主目录前缀
- reuse-first / 已有基础设施检查，以及不能破坏明确边界的限定
- 人类可读代码、长任务定期重构与中间产物规模约束
- 人类与 Agent 共用正式 CLI
- 批处理/长任务日志
- 低成本生产默认项，含配置校验、生产模式、可重复构建及静态/文本压缩责任检查
- docs 只保存原生载体难以表达的稳定知识，不保留任务状态
- 大改动前的五项说明与 Design/ADR 准入
- 长任务最终成果、verifier、阶段可复核/可重建
- 重复运行自纠偏、旧 plan 非权威
- 若属于 `.super`，跨仓能力与共享规则

## 删除旧结构

只有确认旧 `.ai/` 中所有有价值内容都有明确去向，且人类意图没有被误删后，才删除 `.ai/`。

## 输出

最后给：

- 迁移表
- 删除项及理由
- 新 `AGENTS.md` 关键变化
- 协议参考基线、已删除/替代条款、全部目标仓的处理状态和验证结果、未同步项及原因
- 需要人类手工处理的 owner 内容
- 仍未解决的问题

除非人类明确要求，不自动 commit/push。
