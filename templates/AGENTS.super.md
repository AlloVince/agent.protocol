## 权威与事实

当前人类指令优先，其次是相关 `owner/` 系统意图；`owner/` 默认只读，只有当前人类明确要求修改具体文件时才可创建、改写或删除。进入子仓后遵守其适用的 `AGENTS.md`；系统目标与局部规则冲突时明确指出，不擅自覆盖。

实际行为以代码、测试、schema、配置和运行结果验证；旧计划与报告只是线索，现有行为也不能自动替代人类目标。

## 跨仓工作

- 总仓只保存跨仓职责、依赖方向、契约、共享能力和整体验收方式，不复制子仓内部百科。
- 统筹多个 Agent（leadership）时，为子任务明确输入、输出、边界、依赖和验收；子 Agent 遵守所在仓规则，总 Agent 负责接口一致性、集成与最终用户成果。
- 从总仓进入子仓工作（copilot）时，先定位责任仓、共享能力与受影响契约，再按子仓入口执行，同时遵守适用的系统边界。
- 新增基础能力前检查各仓内部库、服务、正式 CLI 和数据模型，优先集成/扩展。只有能力不足或复用会破坏明确的依赖、部署、数据边界时才新增，并先说明原因。
- 重复操作使用人类也使用的正式 CLI/标准入口，缺失时扩展正式入口，不保留 Agent 私有操作路径。

## 大改动与长任务

- 架构、核心模型、技术栈等大改动前说明问题、现有能力为何不够、最简方案、影响和验收；可在当前对话说明，不强制落文档或新增审批流程。
- 代码使用清晰命名、直接控制流和显式数据变化；避免过度抽象、复杂泛型、元编程与隐式魔法，遵循项目已有模式。
- 每个可验证阶段结束前检查并重构本任务累积的代码，发现膨胀及时按职责整理、合并重复与清理废弃实现；禁止持续累积超长函数、超大源文件和混杂职责，保护用户改动并验证行为。
- 中间产物随规模采用已有分块、流式或存储能力，禁止堆积需整量载入/重写的超大单体；格式强制的单体输入/交付文件保持兼容，处理资源仍须有界。保护不可重建输入，清理可重建且不再使用的临时产物。
- 总 Agent 的阶段验收包括代码与产物约束；最终按用户成果提供真实证据，不能以“子任务全部完成”替代整体验收。下一步明确、已获授权且无真实阻塞时继续。
- 复用既有日志、测试和产物机制，不另建重构 workflow、统一行数配额或重型存储；不混入无关重构，不为绿灯弱化测试，说明未验证项和真实阻塞。

## 文档与共享规则

`README.md` 与 `owner/` 面向人类；docs 只保存长期有效、原生载体难以表达且能减少未来 Agent 误判、探索或重建成本的信息。当前焦点、进度、下一步、一次性 debug 过程和 session 流水账不进入 docs；使用当前对话或已有任务载体，不另建 memory。

大改动的设计只有持续有用时才落普通 docs；存在高返工、真实取舍且理由长期有用时可写 ADR。过期内容应修正或删除。

共享规则只接纳反复跨仓发生的问题、系统边界或能稳定减少多个仓误判的约束：

- 在总仓形成最小规则，逐仓语义比较；把独立进入子仓时必需的约束同步到该仓入口，不要求读取整套总仓文档。
- 保留更具体的本地约束，冲突明确报告，不整文件覆盖；代码/配置已强制的事实不重复写。
- 同步包含新增、修改、删除和替代；仅删除已确认废弃的共享条款，来源不明时保留并报告。

## Protocol 升级与交付

- 确认仓库角色与授权范围，比较旧协议、新版本与当前项目定制；总仓用 super 模板，子仓用 project 模板。
- 在本总仓发起升级默认覆盖总仓及全部已声明子仓，除非人类限定范围或只要求 review/预览；从已有地图核实清单，固定同一协议来源，先总仓后逐仓应用，无需重复确认。不修改 `owner/`，不覆盖已有工作；单仓受阻继续处理其余不受影响的仓。
- 用普通注释或 Git 记录保留已核实的参考 tag/commit，未发布修改如实标注，不新增同步配置体系。
- 对照完整清单报告各仓已更新、无需变更、部分完成或未处理的状态，以及约束增改删、验证结果与未同步原因；部分同步不能声称全系统完成。
- 除非人类明确要求，不自动 commit / push / release。
