# AGENTS.md — agent.protocol

## 目的

维护一套轻量、可迁移、尽量采用社区文件习惯的 Agent 工程协议。

本仓不包含业务运行时代码。修改本仓时，目标不是增加规则数量，而是用最小规则解决反复出现的 Agent 工程问题。

## 权威

1. 当前人类指令
2. `README.md` 中已确定的协议目标
3. 本文件
4. `docs/` 中对应规范
5. 历史版本与旧实现

旧结构不是兼容目标；不要因为历史上存在 `.ai/`、memory、workflow 就恢复它们。

## 本仓结构

- `README.md`：给人看的协议说明
- `CHANGELOG.md`：给人看的版本变化
- `templates/`：生成/更新业务仓 `AGENTS.md` 的模板
- `bootstrap/`：一次性接入、super 初始化、升级剧本
- `docs/`：给维护协议的 Agent 使用的规范

## 维护原则

- 优先社区已有文件与原生配置，不创建新的隐藏 Agent 目录
- 新规则必须能解决重复出现、跨任务仍成立的问题
- 能由代码、测试、schema、lockfile、CI/部署配置表达的事实，不再写平行文档
- `docs/` 只保留对未来 Agent 有明确收益的知识
- `owner/` 的语义必须保持“人类长期意图、Agent 默认只读”
- 模板必须强调 reuse-first、共享 CLI、人类可读代码、长任务证据与生产默认项
- `.super` 只提供跨仓上下文与共享规则，不替代子仓 `AGENTS.md`

## 变更检查

修改协议时至少反查：

- 是否重新引入私有文件系统或 session memory
- 是否把工具/语言偏好误当成项目事实
- 是否让 Agent 可以绕开已有内部基础设施
- 是否允许 Agent 用私有脚本执行人类也需要的正式运维
- 是否弱化了代码可读性
- 是否会让长任务只完成“阶段”而没有最终可见成果
- 是否保留阶段 verifier、日志、证据、可重建性
- 是否兼容普通单仓与 `.super` 多仓
- 是否会覆盖 `owner/` 或项目本地规则

## 完成

完成前检查模板、bootstrap、README 与相关 docs 是否语义一致。除非人类明确要求，不进行 Git commit/release。
