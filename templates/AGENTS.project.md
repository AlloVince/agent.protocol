## 权威与事实

当前人类指令优先，其次是相关 `owner/` 长期意图、适用的 `AGENTS.md`（更近目录规则更具体）。`owner/` 默认只读，只有当前人类明确要求修改具体文件时才可创建、改写或删除。

实际行为以代码、测试、schema、配置和运行结果验证；docs、旧计划和报告不能代替验证。发现意图、规则与实现冲突时明确指出，不把现有行为自动当成正确目标。

## 复用与正式操作入口

- 新增 CLI、logger、config、storage、queue、HTTP client、validation、deployment 等基础能力前，先查当前仓、workspace、内部库、已有服务与已声明的 `.super` 共享能力。
- 优先集成或扩展已有层。只有能力不足或复用会破坏明确的依赖、部署、数据边界时才新增，并先说明缺口或边界原因；不得因图快留下第二套永久实现。
- 开发、构建、测试、抓取、转换、导入、迁移、索引、部署、维护和诊断等重复操作，必须使用人类也使用的正式 CLI / package scripts / 标准任务入口；缺失时先扩展正式入口。
- 一次性调查可用临时代码；承担重复或正式流程后必须收敛到已有库与正式入口，不保留 Agent 私有操作路径。

## 人类可读与改动纪律

- 使用清晰命名、直接控制流、显式数据流和副作用；遵循项目已有模式，注释解释原因与非显然约束。
- 避免过度抽象、复杂泛型、元编程、隐式魔法、层层 helper 和压缩表达式；确有必要时说明收益，不把理解成本转嫁给维护者。
- 禁止持续堆积超长函数、超大源文件、混杂职责、重复实现和废弃分支；按职责整理，不能用机械拆文件或增加抽象层掩盖复杂度。
- 不混入无关重构、升级或格式化，不为假想需求增加服务与依赖，不静默改变接口、数据语义和系统边界。
- 架构、核心模型、技术栈等大改动前，简要说明：问题、现有能力为何不够、最简方案、影响、验收方式。可在当前对话说明，不强制落文档或新增审批流程。

## 工程默认线

- 主动落实当前项目适用、成熟且低成本的基线：配置校验、生产模式、可重复构建、错误处理与超时、密钥管理、合理缓存和静态/文本响应压缩；已有 CDN/反代承担的能力不重复建设。不采用时说明具体原因。
- CLI、批处理和长任务提供适量阶段/进度、失败原因、最终摘要与退出状态，避免长时间静默；复用已有日志设施。

## 文档准入

生成或更新 `AGENTS.md`、`README.md`、`docs/` 文档时，标题与说明正文默认使用简体中文；代码标识符、命令、路径、配置键、专有名词与必要原文引用保留原样。仅当前人类指令或项目明确的语言规则可覆盖此默认值，不能仅因现有文档或源码为英文就切换语言。不为统一语言批量翻译无关文档；`owner/` 仍遵守只读边界。

`README.md` 与 `owner/` 面向人类；`docs/` 只保存能持续减少未来 Agent 误判、重复探索、上下文或重建成本的稳定知识。代码、测试、schema、配置或 CLI help 能准确表达的内容优先回归原生载体。

不保存 session 流水账、当前焦点、进度、下一步、一次性 debug 过程或 Git 已表达的变化；长任务也不例外。进度使用当前对话或项目已有任务载体，不另建 memory/workflow。过期 docs 应修正或删除。

设计只有持续指导后续实现且难从代码恢复时才写普通 docs；高返工、存在真实取舍且理由长期有用时可写 ADR。无需空分类、重复文档或固定设计流程。

## 长任务与交付

- 先明确最终用户成果与可观察验收条件；每轮核对当前代码、数据和实际产物，研究工具和阶段完成不能替代最终成果。下一步明确、已获授权且无真实阻塞时继续。
- 每个可验证阶段结束前，定期检查并重构本任务累积的代码：拆分混杂职责、合并重复逻辑、清理已废弃的实验实现；发现膨胀及时处理，不拖到最终交付。保持行为并运行相关验证，保护用户已有改动。
- 禁止把持续增长的数据、日志、二进制或多阶段结果堆成超大单体中间产物；按实际规模使用可独立处理的分块、流式读写或项目已有存储，避免整量载入、重写。格式强制的单体输入/交付文件保留原格式，处理过程仍须有界。
- 阶段结果应可复核；仅在重建有价值时保存必要输入来源、生成命令和校验信息，复用原生产物机制，不强制阶段目录树。不覆盖不可重建输入；可重建且不再使用的临时产物及时清理。
- 按最初验收条件提供真实证据，运行与变更匹配的测试/检查，不为绿灯弱化测试；说明完成内容、验证结果、未验证项和真实阻塞。
- 除非人类明确要求，不自动 commit / push / release。
