# Protocol 升级原则

协议升级是语义迁移，不是模板覆盖。

## 普通升级

1. 识别普通仓、`.super` 总仓或系统内子仓，确认本次授权的仓库范围
2. 查明旧协议来源，比较旧版规则、新版规则和当前项目定制；总仓使用 super 模板，普通仓和子仓使用 project 模板
3. 明确新增、修改、删除和替代的条款，只迁入适用部分；确认来自旧协议且已废弃的条款应删除，不能只增不减
4. 保留项目自己的目标、边界、命令和特殊约束；来源不明或冲突的规则先保留并报告，不能误作旧协议残留删除
5. 不自动修改 `owner/`，不为了“版本一致”创建无用 docs
6. 核对真实导航、正式 CLI 与共享能力入口；按 `docs/spec.md` 检查并修正个人机器路径泄露，保留导航用途，报告无法确认的入口及未同步项

## 来源与多仓范围

优先利用已有 Git 记录识别来源；接入/升级完成后，可在 `AGENTS.md` 顶部用一行普通注释记录协议仓 URL 与已核实的 tag/commit，表示参考基线而非与模板完全一致。不新增版本配置文件或同步运行时。使用未发布工作树修改时注明“基于某 commit，含未发布修改”，不能只按 README 版本号声称已使用某个 release；来源不明则明确未知。

在 `.super` 总仓发起升级任务，默认范围是总仓及其明确声明的全部子仓，一次发起即可逐仓应用，无需重复确认；人类明确限定范围或只要求 review/预览时除外。普通仓或单个子仓发起的任务默认仅修改当前仓，读取系统约束不扩大修改范围。

先从总仓已有声明枚举并核实所有目标仓，固定本轮协议来源，再更新总仓、逐仓更新子仓，并处理已废弃或被替代的共享条款。保留各仓已有工作；无法读取、无法安全合并或存在冲突的部分报告未同步，继续处理其余不受影响的仓。最终对照完整清单给出每仓状态及验证结果，已经符合的仓无需制造改动，部分完成不得宣称全系统完成。

这是一次 Agent 任务中的多仓修改，不是 Git 自动传播或跨仓原子提交；commit/push 仍需人类明确要求。具体执行步骤见 `bootstrap/upgrade.md`。

具体多仓边界见 `docs/multi-repo.md`。升级是当前任务，不要求把迁移报告保存为长期 docs。

## 从 v0.2 / `.ai` 迁移

旧内容按性质处理：

### `.ai/defaults/preferences.md`

- 项目级长期工程约束 → 合并进 `AGENTS.md`
- 真实运行时/包管理器版本 → 原生配置/lockfile
- formatter/linter 偏好 → 原生工具配置
- 个人模型/工具偏好 → 用户全局 Agent/IDE 设置
- 没有实际约束力或只是个人习惯的内容 → 删除

### `.ai/defaults/ai-coding.md`

只保留仍然能改变 Agent 行为、且没有被新模板覆盖的项目特例，合并进 `AGENTS.md`。

### `.ai/memory.md`

- 稳定且未来 Agent 需要的事实 → 合适的 `docs/`
- 人类长期意图 → 不由 Agent 自动写入 `owner/`；列给人类确认/手动迁移
- 纯当前进度 → 不进入 docs；尚未完成的任务在当前对话或已有任务载体交接后删除旧状态文件，不新建替代 memory
- 雷区/调试结论 → 只有确实能避免未来重复损失时才进 docs
- 流水账 → 删除，交给 Git 历史

### `.ai/workflow/*`

不保留 workflow 系统。高价值行为约束应已经进入根 `AGENTS.md` 或 protocol 模板；其余删除。

## 删除旧目录的时机

在确认所有仍有价值的内容已经迁移或明确丢弃后，再删除 `.ai/`。不要先删再猜里面有没有需要保留的人类意图。
